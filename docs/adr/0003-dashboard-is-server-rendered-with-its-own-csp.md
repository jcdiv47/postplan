# The Dashboard is server-rendered with no build step, under its own CSP

The Dashboard is plain HTML generated by pure functions in `ui.mjs`, with one
hand-written stylesheet and ~50 lines of JavaScript served from `public/`. No
framework, no bundler, no build step — `node postplan.mjs serve` remains the
whole deployment story, and `parse5` remains the only dependency.

Draft serving and the Dashboard get *different* Content-Security-Policy headers.
Drafts keep `script-src 'none'`, which is what makes it safe to store uploaded
HTML byte-for-byte with inline `<script>` in it. The Dashboard gets
`default-src 'none'; script-src 'self'; style-src 'self'; form-action 'self'`.

## Considered options

Allowing `script-src 'unsafe-inline'` on the Dashboard would avoid the static
file routes. Rejected: Draft titles are extracted from uploaded HTML, so they
are attacker-controlled, and they are rendered on the one page that holds the
session cookie. Keeping inline script blocked means HTML-escaping and the CSP
are two independent defences rather than one — a missed escape stays a layout
bug instead of becoming script execution.

## Consequences

Static assets are served by an explicit path-to-file map, not by serving a
directory, so no user-controlled string ever reaches the filesystem and the
server gains no path-traversal surface.

Asset paths resolve from `import.meta.url`, not `process.cwd()`, because the CLI
is `npm link`ed and runs from arbitrary working directories.
